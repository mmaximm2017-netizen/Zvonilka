# Звонилка 0.11.6

Нативная Android-звонилка, разрабатываемая и проверяемая в первую очередь для Samsung A15 / Android 16.

Техническая база: Kotlin 2.1.20, Jetpack Compose, Material 3, Android Telecom, compileSdk/targetSdk 35, minSdk 29.

## Что реализовано

- Три вкладки: «Недавние», «Контакты», «Клавиши».
- Журнал вызовов с отдельной строкой на каждый вызов, фильтром пропущенных, датой, временем и длительностью; последний снимок хранится локально для мгновенного холодного показа и затем тихо сверяется с системным журналом.
- Удаление отдельных и выбранных записей журнала с подтверждением.
- Локальные контакты: создание, редактирование, несколько номеров, основной номер, фото, удаление.
- SIM-книга ADN на Android 12+: чтение, объединение с локальными контактами, создание, редактирование и удаление, если устройство и SIM это разрешают.
- Ручной VCF import/export: vCard 2.1/3/4, quoted-printable, фотографии, несколько номеров, ограничения размера и защита от точных дубликатов.
- T9 с русскими и латинскими буквами; найденный номер сначала подставляется в строку набора, звонок запускается отдельной зелёной кнопкой.
- Выбор SIM по умолчанию и для конкретного контакта; запоминается фактически использованный телефонный аккаунт после соединения.
- Экран вызова в стиле iPhone: фото/фон, имя и статус, слайдер ответа, завершение активного звонка, mute, динамик, аудиовыход, DTMF, удержание и добавление вызова.
- Физические клавиши громкости отклоняют входящий вызов. Системная кнопка питания не перехватывается.
- Датчик приближения во время активного разговора через разговорный динамик, если он поддерживается устройством.
- Переворот телефона экраном вниз после распознанного положения экраном вверх запрашивает `TelecomManager.silenceRinger()`.
- Собственные уведомления пропущенных вызовов с объединением по номеру, обратным вызовом и счётчиком на вкладке «Недавние».
- Защищённый `SystemMissedReceiver` принимает делегированные Telecom события пропущенных, чтобы не показывать одновременно системное и собственное уведомление.
- Опциональная проверка неизвестных входящих через публичный PhoneBlock API. Выключена по умолчанию; при включении PhoneBlock получает номер и IP. Контакты и журнал не отправляются.
- Светлая, тёмная и системная тема.
- Диагностика звонков без записи номеров и имён контактов.


## 0.11.6: финальный пакет после аудита

- Исправлено зависание общего состояния загрузки после операций изменения данных.
- Повторные `refresh()` теперь отменяют предыдущую публикацию, поэтому старый запрос не может перезаписать более свежий результат.
- Последний снимок журнала хранится только во внутреннем приватном файле приложения и показывается сразу после холодного запуска; затем журнал перечитывается из Android CallLog.
- `InCallService` сначала загружает локальные контакты и сразу обновляет имя входящего, не ожидая более медленного чтения SIM-книги; SIM-контакты присоединяются вторым этапом.
- CI для пользовательского APK переведён с debug-варианта на non-debuggable release (`assembleRelease` + `lintRelease`). Приватный ключ по-прежнему не попадает в GitHub/CI.
- Добавлены unit-тесты кодека локального снимка журнала.

## 0.10.2: исправления после аудита

- Фоновая очистка системного пропущенного больше не помечает прочитанными все непрочитанные MISSED-записи журнала.
- При известном номере изменяются только записи с совпадающим нормализованным номером и только в количестве, которое Звонилка считает своим.
- Широкая отметка всех пропущенных как прочитанных выполняется только при явном пользовательском просмотре/очистке пропущенных.
- Делегированные Telecom события вынесены в отдельную тестируемую политику: нулевой callback игнорируется, существующий собственный счётчик имеет приоритет, после холодного старта счётчик может быть восстановлен из Telecom.
- Добавлены unit-тесты этой политики.
- Ошибки SIM-книги теперь различают отсутствие разрешения, неподдерживаемое устройство/операцию и неожиданный runtime-сбой; неожиданные ошибки попадают в локальную диагностику.
- PhoneBlock User-Agent использует фактическую версию приложения.
- GitHub Actions выполняет unit tests, сборку debug APK и lint не только после push в `main`, но и для pull request в `main`.

## Известные ограничения

- Android Telecom и поведение полноэкранного входящего вызова зависят от прошивки и системных настроек. Финальная приёмка выполняется на реальном Samsung A15 / Android 16.
- Доступ к SIM-книге зависит от Android, прошивки, оператора и самой SIM. SIM-контакт хранит один номер и имя без фотографии.
- Автоматические резервные копии контактов и ротация файлов не реализованы.
- PhoneBlock является только источником возможной spam-оценки. Он не определяет организации и не является подтверждением безопасности номера.
- Экстренные вызовы не должны тестироваться ради проверки приложения; соответствующий системный UI обслуживает Android/предустановленная звонилка.
- `CallStore` остаётся процессным слоем состояния между `InCallService` и UI. Широкий архитектурный рефакторинг намеренно не выполнялся в 0.10.2, чтобы не повышать риск регрессий телефонной части.

## Что проверить на телефоне

1. Назначение Звонилки приложением телефона по умолчанию и все требуемые разрешения.
2. Исходящий и входящий вызов при разблокированном и заблокированном экране.
3. Ответ слайдером, отклонение клавишами громкости, завершение разговора.
4. Один пропущенный вызов, два пропущенных подряд от одного номера и от разных номеров; отсутствие двойных уведомлений Samsung/Звонилки.
5. Открытие «Недавних»: уведомления и счётчик должны очищаться, строки истории должны оставаться.
6. Две SIM: выбор по умолчанию, выбор для контакта, временно недоступная ранее выбранная SIM.
7. Mute, динамик, Bluetooth/гарнитура, DTMF, удержание и второй вызов.
8. Создание/редактирование локального и SIM-контакта, в том числе отказ SIM от записи.
9. VCF import/export на тестовых контактах с русским текстом, несколькими номерами и фотографией.
10. PhoneBlock только при осознанно включённой настройке.

## Сборка

Требуются JDK 17, Android SDK 35 и Gradle 8.11.1.

```bash
gradle :app:testDebugUnitTest :app:assembleRelease :app:lintRelease --no-daemon
```

GitHub Actions workflow `Build APK` выполняет ту же проверку для `main` и pull request в `main`.

## Подпись APK

Начиная с 0.8 пользовательские APK подписываются постоянным приватным ключом вне GitHub. CI выдаёт unsigned release APK и `apksigner.jar` только как входные данные для локальной подписи.

`scripts/sign-apk.sh` проверяет публичный отпечаток из `signing-certificate.sha256`. Приватный ключ и пароли запрещено коммитить, публиковать в CI или артефактах GitHub. При отсутствии существующего ключа нельзя генерировать новый как замену: для совместимого обновления нужно восстановить исходный приватный пакет владельца.

## Приватность

Репозиторий публичный. В коде не должны храниться приватные ключи, пароли, содержимое контактов или журналы вызовов пользователя. Диагностический журнал приложения хранится локально и не должен включать номера или имена.
